## B. Bugs Found

### P0 — Application did not start / fatal runtime errors

| # | Symptom | Root Cause | File | Fix Applied | Status |
|---|---------|------------|------|-------------|--------|
| 1 | Vite failed to compile React bundle; browser stuck on "Loading CyberNet Lab v4.0..." | `const next` declared on line 54 of WorkflowEngine.js was reassigned on line 61 (`next = unlockNextStep(...)`). Reassigning a `const` is a compile-time error, blocking esbuild/Vite from scanning the module graph. | `frontend/src/engine/WorkflowEngine.js` | Changed `const next` to `let next` on line 54 | FIXED |
| 2 | React runtime error: `Set.sort is not a function or its return value is not iterable` | `LabExplorerView.jsx` line 35 called `.sort()` directly on a `Set` object: `new Set(labs.map(l => l.category)).sort()`. `Set` has no `.sort()` method. | `frontend/src/app/views/LabExplorerView.jsx` | Changed to `['all', ...[...new Set(labs.map(l => l.category))].sort()]` | FIXED |
| 3 | `npm install` / build pulled in React-19-only peer dependencies | `@react-three/drei@10.7.8` and `@react-three/fiber@9.7.0` require React 19, but the project uses React 18.3.1. This caused peer-conflict warnings and risked runtime incompatibility. | `package.json`, `package-lock.json` | Downgraded to React-18-compatible versions: `@react-three/fiber@8.15.0`, `@react-three/drei@9.88.0`, `three@0.150.0` | FIXED |
